## 二、生产阻塞项处理进度

下列技术阻塞项已有实现与测试；这不代表允许跳过使用者验收，也不代表已获准使用无人值守写入。

- [x] **整批提取与索引事务**：两者均先解析全部输入，再整批提交数据库；提取中的项目创建、文件元数据、词条和全文索引更新处于同一事务，后续文件或数据库写入失败时不会留下半批结果。工单是独立的原子文件发布，不与数据库组成跨资源事务：数据库已完整提交但工单发布失败时，会明确报错并保留原工单，不声称数据库已回滚。
- [x] **原文删除和数组重排后的同步**：一次提取代表完整源目录快照；删除文件、删除字段以及变为空白的字段退出当前查询、保存、统计、搜索和数据库注入，历史译文保留在数据库中。数组逐层使用带类型的 `id` / `key` / `index` 对齐，重排保留词条 ID 和人工译文；重复、混用或缺失的标识明确报错。没有记录标识的数组只有位置身份，原文变化必须人工复核，不宣称能推断其语义身份。旧数据库首次绑定数组标识时，已有译文降为待复核；锁定记录发生原文变化则拒绝整批提取。
- [x] **提取结果统计一致性**：报告按本次扫描字段对应的数据库实际记录统计，保留的人工译文不会重新算成未翻译；新增 `needs_review`（待人工复核）计数，单独呈现原文变化或 QA 未通过的已有译文，不将其计入已审校。
- [x] **翻译记忆库（TM）的匹配与去重**：重复导入相同记录不会新增副本，同时核对哈希和原文，优先采用同文件候选；适用范围内存在不同译文时标记为歧义，不自动预填。同文件匹配命名为 `FileExact`，不再暗示已经验证同一指针上下文。现有数据库中的历史重复记录不会被自动删除，避免未经授权清理数据。
- [x] **资源路径规范化**：只去掉各路径段开头的一次 `KR_`，保留名称中间的同名子串；提取、索引与注入共用源文件映射，映射冲突会在写入前报错，嵌套前缀目录的提取与注入往返已通过测试。
- [x] **异常中断后的恢复与持久化**：新增 `lct restore`，校验备份清单、工作区、路径、原始文件和注入结果的 SHA-256；仅恢复属于该操作的文件，拒绝覆盖无关修改。注入与恢复共享操作系统文件锁；持久化操作记录和备份清单后才替换目标，在 Unix 上同步文件及目录。真实 CLI 进程在 1000 文件批次中途被终止后，成功还原全部原始字节。恢复可重复执行；整批注入仍不是跨文件原子事务，断电、硬件故障和外部非协作进程的并发改写不在本次实验保证内。
